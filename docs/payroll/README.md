# התאמת תעריפים שעתיים — יולי מול אוגוסט 2026

`build_rate_reconciliation.py` מייצר את `התאמת-תעריפים-יולי-אוגוסט-2026.xlsx`.

## מאיפה מגיע התעריף

לא מחישוב משוער אלא מהתלוש עצמו:

```sql
raw -> 'wageComponentsById' -> <id> ->> 'price'
   where componentName in ('משכורת','משכורת אחמש/מארחת')
```

בטבלה `buk_payroll`. שדה `working_hours` הוא שעות הבסיס בלבד; שעות הנוספות יושבות
ברכיבים `ש.נוס 125%` ו-`ש.נוס 150%` עם `quantity` נפרד.

**אימות:** רכיבי הנוספות מתומחרים כאחוז מהתעריף, ולכן כשהתעריף יורד מ-51 ל-36
רכיב 125% יורד מ-63.75 ל-45 ורכיב 150% מ-76.50 ל-54. זה מאשר שה-`price` שנקרא
הוא באמת התעריף השעתי.

## חישוב הפער

```
שעות משוקללות = שעות בסיס + 1.25 × שעות 125% + 1.5 × שעות 150%
פער בשכר      = (תעריף יולי − תעריף אוגוסט) × שעות משוקללות אוגוסט
```

ברוטו, לפני מס.

## הממצא

10 עובדים ירדו בתעריף, סה״כ ₪10,173.71. כל הירידות נחתו בדיוק על מדרגות
התעריף הסטנדרטיות (35.40 / 36 / 40 / 51) — דפוס שמתאים לטבלת תעריפים שנבנתה
מחדש ואיבדה תעריפים אישיים, ולא להחלטה פרטנית לגבי עשרה אנשים.

## הערה על אימות הקובץ

`recalc.py` לא רץ — LibreOffice בקונטיינר הזה נכשל בטעינת כל קובץ xlsx, כולל
קובץ טריוויאלי בן שלושה תאים (`source file could not be loaded`). במקום זה כל
עשר הנוסחאות אומתו מול חישוב SQL עצמאי, והסכום תואם עד האגורה. הנוסחאות נשמרו
בקובץ ללא ערכים מטומנים — אקסל יחשב אותן בפתיחה.
